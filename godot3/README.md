# Biosplit 2 — Godot 3 / C#

Откройте `project.godot` в **Godot 3.5/3.6 Mono**, соберите C# кнопкой Build и нажмите F6/F5. Требуется .NET SDK с поддержкой сборки net472. Обычная версия Godot без Mono и Godot 4 не подходят.

## Управление

- Кнопки интерфейса или 1: удар (12 урона, +10 ярости).
- 2: выстрел (40 урона, стоит 30 ярости). В начале заблокирован; доступен после трёх ударов. Ярость сохраняется между противниками, максимум 100.
- 3: уворот на 0,65 с; восстановление 1,1 с.
- 4: блок на 1 с, снижает входящий урон с 15 до 3.
- I / Escape: инвентарь и пауза боя. Аптечка лечит 40 HP.
- R: начать заново.

Противник атакует раз в 2,4 секунды, предупреждая за 0,8 секунды. Победа даёт 10 монет; каждая третья победа даёт аптечку. Новые противники имеют больше здоровья. Начальные ресурсы: 100 HP, 0 ярости, 2 аптечки.

Каждый успешный удар смещает панораму влево на 32 пикселя с плавным переходом. Фон повторяется узлом ParallaxLayer с Motion Mirroring. Исходное JPG повторяется без редактирования: если его края не совпадают, стык остаётся видимым.

## Структура и настройка

`Scenes/Main.tscn` — стартовая сцена. `Scripts/Main.cs` — управление боем, UI, инвентарём и узлами сцены. `Assets/` — копии предоставленных изображений, проект не зависит от внешней папки Images.

Выберите Main в сцене: экспортированные параметры задают урон, стоимость выстрела, ярость за удар, смещение фона и интервалы атак. Значения по умолчанию рассчитаны для прототипа; ShotCost следует держать в диапазоне 1–100.

Используются две предоставленные позы для каждого персонажа. Уворот изображается перемещением, защита — голубой дугой; звук и дополнительные кадры анимации не добавлены. Инвентарь хранится в памяти текущего забега.

## Проверка при запуске

1. Выстрел заблокирован до третьего удара; после выстрела ярость уменьшается на 30.
2. Каждый удар сдвигает фон влево; повторение сохраняется после нескольких ширин панорамы.
3. Нажмите уворот или блок во время предупреждения об атаке: полученный урон равен 0 или 3 соответственно.
4. Инвентарь останавливает таймеры боя; аптечка расходуется только при неполном здоровье.
5. Победа приносит монеты и нового врага; при 0 HP бой останавливается, R перезапускает сцену.

Документация C#: https://docs.godotengine.org/en/3.5/tutorials/scripting/c_sharp/c_sharp_basics.html

## Редактирование UI в Godot

Откройте Scenes/Main.tscn и раскройте Main → UI → HUD. Все кнопки, подписи, полосы и фоновые панели находятся в сцене; их размеры, якоря, отступы, иконки, Theme и StyleBox редактируются через инспектор. Код не меняет геометрию UI. Сигналы pressed подключены в самой сцене.

Inventory виден в редакторе для настройки; при запуске код скрывает его до нажатия I. Чтобы редактировать HUD под ним, временно выключите видимость Inventory в дереве сцены. Имена и пути узлов используются в Main.cs: при переименовании обновите GetNode. Динамические значения HP, ярости, статуса боя и содержимого инвентаря обновляются во время игры.

## TouchScreenButton и мышь

Все семь кнопок используют TouchScreenButton с C# скриптом TouchActionButton. В редакторе каждый узел кнопки содержит Card, Icon (у боевых кнопок), Caption и TouchButton. Родительский Control сохраняет редактируемые якоря и размеры; область нажатия TouchButton автоматически заполняет родителя. Подписи находятся в Caption, сигналы pressed подключены у TouchButton. Disabled реализован в скрипте: выключает обработку ввода и затемняет кнопку, сохраняя её на экране.

Project Settings → Input Devices → Pointing → Emulate Touch From Mouse включён (`input_devices/pointing/emulate_touch_from_mouse=true`). Обратная эмуляция мыши из касаний отключена. Visibility Mode = Always, поэтому кнопки работают на компьютере и сенсорных устройствах.

Проверено в Godot 3.6.3 Mono: события левой кнопки мыши через эмуляцию касаний вызывают один удар (+10 ярости), открывают и закрывают инвентарь.


## Фон и участники боя в редакторе

В Main.tscn вся графика описана узлами сцены. Main.cs не создаёт Sprite, не загружает текстуры и не содержит _Draw.

- Background → Panorama → Image: ParallaxBackground, ParallaxLayer и Sprite. Image использует battle_01.jpg 960×540; горизонтальный Motion Mirroring у Panorama равен 960. При замене панорамы или изменении её масштаба обновите интервал повторения, чтобы он совпадал с её шириной. Сохранено пользовательское окно 960×540 со stretch/aspect=keep.
- Combatants → Player и Enemy: AnimatedSprite, базовые позиция, масштаб и Flip H задаются в сцене. Код запоминает позиции при старте и добавляет временные смещения для ударов и уворотов.
- Player → BlockShield и Combatants → ShotTrail: Line2D для защиты и выстрела. Видимость управляется состоянием боя.

Выберите Player или Enemy, затем ресурс Frames в инспекторе. В панели SpriteFrames добавляйте кадры и задавайте Speed / Loop. Ресурсы находятся в Animations/PlayerFrames.tres и Animations/EnemyFrames.tres.

Игрок: idle, attack, shoot, dodge, block, hurt, defeat. Враг: idle, attack, hurt, defeat. Пока для отсутствующих поз используются существующие изображения. attack и shoot учитывают число кадров и скорость анимации; кадр не сбрасывается каждый кадр игры. Инвентарь останавливает анимации и прокрутку. Управление позами и боевые таймеры остаются в C#.

Проверены загрузка сцены без создания графических узлов в рантайме, добавление кадров атаки, сохранение позиции из редактора, пауза анимаций, прокрутка через несколько повторов панорамы, механики боя и эмуляция касаний мышью.
